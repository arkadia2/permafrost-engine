********************************************************************************
* 2. 关于                                                                     *
********************************************************************************

    PFMAP是Permafrost引擎用于存储地图数据的自定义ASCII文件格式。该格式严格处理地形数据。
    对象通过加载场景添加到地图中，场景有其自己的PFSCENE格式。PFMAP格式包含材质/纹理列表
    和瓦片列表，组织成32x32的块。每个瓦片具有一些属性，这些属性决定了它的渲染方式和可能具有的
    任何额外行为。

********************************************************************************
* 3. 文件结构                                                                 *
********************************************************************************

    ----------
    3.1 头部
    ----------

    头部正好是4行，按以下顺序排列：

    version         <PFMAP版本号（浮点数）>
    num_materials   <材质列表中的材质数量>
    num_splats      <纹理拼接映射的数量>（版本 >= 1.1）
    num_rows        <地图高度，以块数为单位>
    num_cols        <地图宽度，以块数为单位>

    -----------------
    3.1 材质列表
    -----------------

    接下来是一个包含恰好<num_materials>个材质的列表，每个材质占一行。每行以标识符"material"开头，
    后面是材质名称（不含空格）和材质纹理的文件名（也不含空格）。一个材质行的示例如下：

    material Lava-Ground lava_ground.jpg

    --------------
    3.3 拼接列表
    --------------

    接下来是一个包含恰好<num_splats>个纹理到纹理映射的列表。第一个是被拼接图修改的'基础'纹理，
    第二个是应用在基础纹理之上的'强调'纹理。拼接的示例格式如下：

    splat 0 1

    这里，'0'和'1'是之前加载的材质列表中的索引。

    -------------\n    3.3 瓦片列表
    -------------

    接下来是一个包含<num_rows>*<num_cols>*32*32个瓦片的列表。每个瓦片是一个正好24个字符的字符串。
    瓦片可以用空格、制表符或换行符分隔。这意味着瓦片列表可以占用可变数量的行，具体取决于每行中打包
    了多少个瓦片。但是，块中每行的第一个瓦片必须从新行开始。此外，引擎支持的最大行大小为255个字符（包括换行符）。
    PFMAP文件行不得超过此大小。瓦片按块分组。文件中的块按行优先顺序出现。这意味着前32x32个瓦片属于行0列0的块，
    接下来的32x32个瓦片属于行0列1的块，依此类推。在块内部，所有瓦片也按行优先顺序排列。因此，第一行的所有瓦片
    都出现在列表中，然后是第二行的所有瓦片。

    每个24字符的瓦片可以分解为以下字段：

            +-+-+--+--+---+---+-+-+-+-+-------+
    区域:   |A|B|C |D |E  |F  |G|H|I|J|K      |
    大小:   |1|1|2 |2 |3  |3  |1|1|1|1|8      |
            +-+-+--+--+---+---+-+-+-+-+-------+
            
    A - 瓦片类型
    这是一个十六进制数字，合法值范围在0到C之间。解码如下：

        TILETYPE_FLAT              = 0x0（平面）
        TILETYPE_RAMP_SN           = 0x1（南北斜坡）
        TILETYPE_RAMP_NS           = 0x2（北南斜坡）
        TILETYPE_RAMP_EW           = 0x3（东西斜坡）
        TILETYPE_RAMP_WE           = 0x4（西东斜坡）
        TILETYPE_CORNER_CONCAVE_SW = 0x5（西南凹角）
        TILETYPE_CORNER_CONVEX_SW  = 0x6（西南凸角）
        TILETYPE_CORNER_CONCAVE_SE = 0x7（东南凹角）
        TILETYPE_CORNER_CONVEX_SE  = 0x8（东南凸角）
        TILETYPE_CORNER_CONCAVE_NW = 0x9（西北凹角）
        TILETYPE_CORNER_CONVEX_NW  = 0xA（西北凸角）
        TILETYPE_CORNER_CONCAVE_NE = 0xB（东北凹角）
        TILETYPE_CORNER_CONVEX_NE  = 0xC（东北凸角）

    约定是'北'为'上'（引擎中Z值增加），'西'为'左'（引擎中X值增加）。对于斜坡，第二个字母（例如'SN'中的'N'）
    是升高的一端。对于角，名称中的方向是中央降低的角的方向。'凸'角除了一个点外大部分升高，而'凹'角除了一个点外大部分降低。

    B - 基础高度符号
    合法值为'+'或'-'。允许负基础高度。

    C - 基础高度
    这是一个2位、前导零填充的十进制数字，表示瓦片的基础高度。当基础符号为'-'时，它乘以-1。

    D - 斜坡高度
    这是一个2位、前导零填充的十进制数字，指定瓦片的斜坡高度。对于非斜坡和非角瓦片，此值被忽略。

    E - 顶部材质索引
    这是一个3位、前导零填充的十进制索引，指向材质列表，用于选择瓦片顶面的纹理。

    F - 侧面材质索引
    这是一个3位、前导零填充的十进制索引，指向材质列表，用于选择瓦片侧面的纹理。当斜坡高度大于1时，
    侧面材质也会应用于瓦片的倾斜面。

    G - 可通行标志
    值为'0'或'1'。当为'1'时，瓦片在没有障碍物时是可通行的，否则始终不可通行。

    H - 混合模式
    这是'BLEND_MODE_NOBLEND'（0）或'BLEND_MODE_BLUR'（1）之一。这控制瓦片顶面的纹理如何与相邻瓦片混合。

    I - 法线混合标志
    值为'0'或'1'。当为'1'时，瓦片顶面的法线与周围的法线平均，以创建平滑、连续的边缘。

    J - 不使用凹凸贴图标志
    值为'0'或'1'。当为'0'时，凹凸纹理应用于瓦片的顶面。

    K - 保留
    这些字符保留用于PFMAP格式的未来扩展。它们被引擎忽略。
